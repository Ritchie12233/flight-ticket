# KUL Bug 价雷达 · 产品记录

> 按 product-lifecycle 技能维护。新会话先读本文件，再续接。
> 最近更新：2026-11-11 · 版本：v2（旅行杂志风改版）

## 1. 目标、范围、模式

| 项 | 内容 |
|---|---|
| 产品 | KUL Bug 价雷达：监控吉隆坡出发的错误票价 / 异常低价，推送到手机，网页看板辅助决策 |
| 用户 | 所有者本人 Ritchie（自用；所有者即真实用户） |
| 平台 | GitHub Actions 每 15 分钟扫描 + GitHub Pages 静态看板 + ntfy 推送 |
| 深度 | **轻量**：自用、单用户、无付费、无敏感数据。市场 / 运营 / 客服 / 多人权限 = 不适用 |
| 使用场景 | 手机：收到推送 → 核实 → 下单；电脑：随手浏览找出行灵感（用户确认两者都要） |
| 非目标 | 账号登录、多人订阅、自建订票、硬抓携程 / Skyscanner（反爬，不做） |

## 2. 核心任务（来自所有者的明确需求，非模拟研究）

| ID | 任务 | 关键时刻 | 现状（v1） |
|---|---|---|---|
| T1 | bug 价出现时第一时间知道 | 推送到达的那一刻 | ✅ ntfy 已验证送达 |
| T2 | 判断「这价是真的吗、值不值得订」 | 打开推送 / 看板的前 10 秒 | ⚠️ 只有判定理由；缓存价未实时复核 |
| T3 | 快速去平台核价下单 | 点按钮 | ✅ Aviasales / 携程 / Skyscanner / Google 四个入口 |
| T4 | 盯住「我真正会去的航线」 | 平时随手打开 | ❌ 目标价只在 config 里，看板上看不到「我的航线现在多少钱、离目标还差多少」 |
| T5 | 没有 bug 价时也找到出行灵感 | 电脑上闲逛 | ⚠️ v1 有榜单，但像数据表，没有「想出发」的感觉 |

所有者对 v1 的反馈：**不喜欢布局、颜色和整体设计**（深蓝网格 + 琥珀色）。选定方向：旅行杂志风（米白底、衬线标题、暖色）。

## 3. 可行性（已实测）

- Aviasales Data API：经济舱 v2、商务舱 v3 均实测可用，每轮约 1150 条票价 / 820 条航线；报价来源含 Trip.com。
- 携程 / Skyscanner 自动抓价：**不做**。携程接口需伪造客户端身份，Skyscanner 有人机验证；改为一键查价链接（携程链接已实测，Skyscanner 链接遇人机验证未能实测）。
- GitHub 定时触发：**实测不可靠**（部署后 3.5 小时一次未触发）。已改为每轮结束后自动预约下一轮（接力），定时触发保留作保底。接力的有效性待 v2 发布后复查。

## 4. 需求与验收标准（v2）

| ID | 需求 | 验收标准 | 状态 |
|---|---|---|---|
| R1 | 首屏「今日焦点」：有异常时展示最强一条；没有时展示最接近 bug 价的一条 | 打开页面，第一屏（桌面 900px 高 / 手机 844px 高）内能看到目的地、价格、日期和「去订票」按钮 | 已实现，截图验证 |
| R2 | 「我的航线」：config 里每个目标价目的地显示当前最低价、目标价、差额、近期走势 | 10 个目标目的地全部显示；已低于目标价的有明显区分；无数据时显示「暂无报价」不报错 | 已实现，截图验证 |
| R3 | 异常低价区：有则卡片展示，无则一句话说明 + 历史数据积累进度 | 空状态不出现大面积空框；进度显示「X / 5 天」 | 已实现 |
| R4 | 出行灵感：按地区浏览，默认国际长途、按性价比排序，可搜索 | 地区切换后数量随之变化；手机上为单列卡片，不出现横向挤压的表格 | 已实现，截图验证 |
| R5 | 情报与推送记录合并为次要区域 | 位于页面下方，不与价格内容抢注意力 | 已实现 |
| R6 | 旅行杂志风视觉：米白底、衬线标题、暖色系，正文对比度 ≥ 4.5:1 | 计算对比度通过；**观感由所有者验收**（AI 不能代替观感验收） | 技术检查通过；观感待你验收 |
| R7 | 手机可用：按钮 ≥ 44px，单手可操作 | 390px 宽截图检查 | 已实现 |
| R8 | 数据新鲜度可见：超过 1 小时未更新时提示 | 状态点变红 + 提示条 | 已实现（沿用 v1） |

延后（下一轮候选，见第 7 节）：推送前实时复核、夜间免打扰、在看板上直接改目标价。

## 5. 信息架构（v2）

```
刊头：KUL FARE RADAR · 更新时间 · 推送状态
导航（吸顶）：今日 · 我的航线 · 异常低价 · 出行灵感 · 情报
① 今日焦点（大幅暖色块：目的地英文大标题 + 中文名 + 价格 + 日期 + 查价按钮）
② 我的航线（目标价目的地网格：当前价 / 目标价 / 差额 / 走势）
③ 异常低价（卡片 或 空状态 + 历史积累进度）
④ 出行灵感（地区筛选 + 明信片式卡片，先显示 24 个，可展开）
⑤ 情报 & 推送记录（两栏，手机上下排列）
页脚：判定规则 · 抢 bug 价小贴士 · 数据源状态
```

术语统一：「常规价」= 该航线近期日最低价中位数；「bug 线」= 按每公里单价算出的 bug 价门槛。

## 7. 运营与迭代（下一轮候选）

| 优先 | 事项 | 理由 | 验证方式 |
|---|---|---|---|
| 1 | 推送前实时复核价格（只对疑似 bug 价调用一次实时搜索） | 缓存价可能已失效，误报会消耗对推送的信任 | 统计 2 周内推送中「点开已失效」的比例 |
| 2 | 夜间免打扰（可配置，bug 价例外） | 自用场景下夜里被普通超值提醒打扰 | 所有者主观反馈 |
| 3 | 在看板上增删「我的航线」（写回 config） | 现在要改 YAML 或让 Claude 改 | 所有者能独立完成一次修改 |
| 4 | 每周日一条周报推送（我的航线价格变化） | 平时没 bug 价时也保持价值感 | 所有者是否点开 |
